# Curriculum audit: Rust worlds 11-mastery and 12-broadcast

Auditor scope: every `quest.toml` and plain `lesson.md` in `content/tracks/rust/worlds/11-mastery` (12 quests) and
`12-broadcast` (19 quests). Starter vs solution checked for 11/01, 04, 05, 06, 08, 09, 10, 11 and 12/01, 03, 05, 06,
08, 09, 11, 12, 17, 19. Games flavours skimmed for 11/01 and 11/10 (world 12 has none). Read before: `docs/CONTENT.md`,
`docs/TRACKS.md`, `docs/tracks/rust-terms.md`, `docs/tracks/rust-12-broadcast.md`,
`docs/PLAYTEST-2026-10-20b-rust-10-11.md`, `docs/REVIEW-2026-10-19.md` (rust/11 section).

**Already known, not repeated in depth:** world 11 spine drift (chunk indexer vs `square!`/text index), the two
back-to-back 14-min proc-macro quests, `thread_local!`/`const {}` unexplained in 11/06, 11/09's source-grep test, three
boss objectives green at start, and the playtest's fixes (examples that were the solution got replaced in world 11).
World 12 has had no playtest or review yet.

What earlier worlds teach (by titles/tags): 00-01 basics through Option/Result; 02 ownership/lifetimes; 03 collections,
iterators, closures, `?`; 04 errors, modules, cargo; 05 traits/generics/`impl Trait`; 06 Box/Rc/RefCell/Cell/Cow/Drop;
07 threads, channels, Mutex, rayon, atomics; 08 tokio, select, streams, cancellation, reqwest (match guards taught in
the 08 boss); 09 bytes, endianness, bits, unsafe, raw pointers, FFI, TCP/UDP; 10 rusqlite, serde, axum, egui, Tauri.
Note: the term ledger `docs/tracks/rust-terms.md` has rows for 00-01 and 12 only, nothing for worlds 02-11, so
"used before taught" cannot be checked mechanically for world 11.

## World 11: Mastery

| Beginner clarity | Experienced-dev value | Coherence / sequencing | Task-lesson fit | Overall |
|---|---|---|---|---|
| 3 | 7 | 4 | 5 | **5** |

**Verdict.** The topics are the right "mastery" topics (macro_rules, proc macros, allocators, profiling, no_std,
wasm), and the experienced dev gets a crisp map of each in a few minutes. But the lessons are dense reference notes, not
the house-style cards: a labelled "**Why now:**" opener, bullet lists stacking four or five ideas, two or three code
blocks, and almost no "situation → it happens → the name". Terms like *token*, *expansion*, *side effect*, *attribute*,
*workspace*, *target*, *O(n²)* arrive unexplained. The exercises often don't practise the concept the lesson is
about (the derive is pre-wired and you write a `format!`; the no_std crate is pre-wired and you write ring-buffer
arithmetic; the wasm quest is a Fibonacci loop plus one copied attribute), and many TODO comments contain the
literal answer, so a beginner can pass without understanding and an expert finishes in a minute.

### Worst quests

- **`11-mastery/04-derive-macro`** ("Write a derive", 14 min / 70 XP). The learner never writes the derive: parse,
  `split_for_impl` and the whole `quote!` are pre-wired; the TODO is a `match &input.data` + `format!` that the TODO
  comment itself spells out. Meanwhile the lesson uses *TokenStream*, *tokens*, *syntax tree*, `#name` splicing,
  `#impl_g #ty_g #where_c`, "cargo workspace" and `proc-macro = true` without a single plain-English gloss. Nothing
  says why generics need the three-piece split (what goes wrong without it). Beginner: lost. Expert: under-challenged.
- **`11-mastery/06-counting-allocations`** (12 min / 60 XP). The biggest code block is an `unsafe impl GlobalAlloc`
  with `Layout`, `*mut u8`, `thread_local!`, `const { }`, `Cell` and nested `unsafe {}` that nobody explains line by
  line, and the learner never touches it. The task is two one-word fixes, both named verbatim in the TODOs
  (`words.join(" ")`, `Vec::with_capacity(input.len())`). "Why does a growing Vec allocate more than once?" (doubling
  capacity, copying the old buffer) is asserted, never shown. Overlaps heavily with 08.
- **`11-mastery/09-wasm-ready-crate`**. *Target*, `target_arch`, *JS glue*, *cdylib*, *rlib*, `wasm-pack` are named
  but not explained; the project never builds for wasm, and the objective that "exports" is a text grep. Most of the
  quest is Fibonacci. Objective label "fib(90) works (iterate, don't recurse)" + test name `..._does_not_overflow`
  is misleading: naive recursion is slow (exponential), not an overflow; `u64` holds fib(90) either way. The "Why now"
  (chunk indexer in a browser) has nothing to do with `fib`.
- **`11-mastery/02-macro-rules-repetition`** (12 min, 4 objectives). At least five new ideas in one quest
  (repetition `$(...),*`, `+` vs `*`, `$(,)?`, literal tokens like `=>`, recursion, absolute `::std::` paths).
  CONTENT.md says one idea per quest. The leading `::` in `::std::collections::HashMap` is never explained (why the
  leading colons?). `::std::cmp::max` is needed by `max!` but only appears in hint 4.
- **`11-mastery/01-macro-rules-basics`** (plain). Never answers the obvious question: *why is `square!` a macro and not
  `fn square(x: i32) -> i32`?* The games flavour does ("functions work on values, macros work on code"); the plain
  lesson does not. "Side effects" is jargon. The TODO comment gives the complete solution.
- **Sequencing:** `05-block-registry` (macro_rules) sits after the two proc-macro quests as a "breather" and has
  `requires = 05-attribute-macro`, so the world goes macro_rules → proc overview → derive → attribute → back to
  macro_rules. It belongs right after 02. Two folders are numbered `05-`.

### Best quests (models)

- **`11-mastery/08-fast-paths`**. Excellent design for experienced devs: correct-but-wasteful code, meters
  (`Counter`, a clone-counting `Name`, an allocation counter) and "same answer, less work". Teaches idiomatic Rust
  habits (entry API, borrow while searching, clone the winner, `&str` over `String`) that experienced devs from other
  languages genuinely lack. The two snippets use different data from the solution. Fix: 4 objectives / 15 min is a lot.
- **`11-mastery/07-read-profiling`**. Short, honest, the right mindset ("measure, change one thing, measure again",
  release builds, width is time). Needs a one-line gloss of O(n²) and "linear scan".
- **`11-mastery/11-boss-optimise-a-slow-crate`**. Deterministic "counts not stopwatches" grading is clever and portable;
  the Toolkit block shows every non-obvious call on other data; rules of the fight are clear.
- **`11-mastery/10-no-std-taste`**: starter TODOs are exemplary for a beginner (each says exactly what changes), even if
  the no_std part is pre-written.

## World 12: Broadcast

| Beginner clarity | Experienced-dev value | Coherence / sequencing | Task-lesson fit | Overall |
|---|---|---|---|---|
| 4 | 8 | 8 | 6 | **6.5** |

**Verdict.** The strongest-designed world of the two: one real project (a Rocket League HUD server) grows module by
module (`frames.rs`, `event.rs`, `feed.rs`, `dedup.rs`, `grace.rs`, ... all present in the boss starter), every quest
opens with a real production problem (Psyonix double goals, Riot's boot burst), lessons follow the kicker-card format,
and the boss genuinely joins the pieces. Experienced devs get real, distinctive Rust (StreamDeserializer for
back-to-back JSON, `broadcast` + `Lagged`, `spawn_blocking`, golden-file tests, Tauri mock runtime). For a beginner it
is hard going: the lessons are very terse, assume a broadcast-tech vocabulary (OSC, Notch, Resolume, Companion, OBS
browser sources, scorebug, stinger, SOS) that is never glossed, and explain *what* each API does but rarely the
*shape* of the code (the loop, the state to keep). Paradoxically, they then hand over the one hard line verbatim: in
at least seven exercises the lesson's only code block equals the last hint or the solution's core line, so the task
becomes "type the loop around the line you were given".

### Worst quests

- **`12-broadcast/11-names-vs-files`** (Levenshtein). For a beginner, the lesson says "the classic table has a row
  per letter of `a`" without ever showing the table, a worked example (`moss` → `mos`), or why the three moves are
  "diagonal + cost / above + 1 / left + 1". Then it prints the exact inner line of the solution
  (`row.push((previous[j] + cost).min(...).min(row[j] + 1))`), which is also hint 2. Dynamic programming is a big idea
  and gets one sentence. `usize::from(bool)` (hint only) is unexplained. Rewrite below.
- **`12-broadcast/12-player-cuts`**. Used-before-taught: the solution needs `img.enumerate_pixels()`, `pixel[3]` as the
  alpha channel, and the `u32::MAX` / `0` sentinel start for min/max; the lesson shows none of them (they're in hint 1
  or nowhere). *Alpha* and *transparent* are not glossed. Meanwhile the `crop_imm` code block is the solution's last line.
- **`12-broadcast/05-grace-period`**. The lesson's code block *is* the whole solution
  (`self.connected_at.is_some_and(|at| now.saturating_sub(at) >= GRACE)`), identical to hint 2. Same pattern in
  **14-off-the-runtime** (`spawn_blocking(work).await.expect(..)`) and **16-tauri-events** (`app.emit("moment", ...)`):
  these are "copy one line" quests. CONTENT.md: "Never put the solution in the lesson."
- **`12-broadcast/08-osc-by-hand`**. "OSC", "Notch", "Resolume", "datagram", "type tags" arrive with little gloss; the
  natural solution uses `std::iter::once(',').chain(...)` which appears only in hint 2 (`.chain` was mentioned once
  in 03/12, `iter::once` never). Fine for an expert, unclear for a beginner how to build the tag string (a `String` +
  `push` loop works and would be simpler to teach).
- **`12-broadcast/09-overlay-socket`**. The lesson shows only the `Lagged` arm; `socket.send(Message::Text(text.into()))`
  (why `.into()`?) is hint-only, and the outer `loop { match updates.recv().await {..} }` shape is never shown.
- **`12-broadcast/15-tauri-commands`** point question is ill-posed: "What does Tauri add to an app that Electron ships
  itself?" with answer "nothing: Tauri uses the system's WebView2...". Reword to "What does Tauri *not* ship that
  Electron does?" with "Chromium" as the answer.
- **All `[[points]]` in both worlds:** every pick-point has `answer = 0` (16/16 in world 12, 9/9 in world 11), and the
  app does not shuffle (`src/lib/components/PointStep.svelte` renders `point.pick` in order). In world 12 the right
  choice is also the longest in ~14 of 16. A learner learns "tap the first, longest one". (The read-quest `[[quiz]]`s
  are fine; the 10-19 playtest fixed those but not the points.)
- **Quest 01 cold build.** Every world 12 crate carries the full dependency set (tauri, axum, image, tokio, csv) and
  `lib.rs` opens with ~10 `#[allow(unused_imports)]` imports of things the quest doesn't use (`tauri::AppHandle`,
  `image::RgbaImage` in a JSON-splitting quest). Shared target makes later quests cheap, but the 4-minute first quest
  carries the whole build; and to a beginner the import wall is noise that looks like it matters.

### Best quests (models)

- **`12-broadcast/13-tokio-or-rayon`** (read). The best lesson in either world: one clear mental model ("tokio is for
  waiting, rayon is for computing, threads for long jobs"), consequences named (frozen HUD), ends with a three-line
  summary. A beginner can follow it; an expert learns the ecosystem view. Quiz is answerable from the text.
- **`12-broadcast/04-one-goal-one-trigger`**. Opens with the owner's real bug report, defines "repeat" precisely before
  any code, explains *why* time comes in as `now` (determinism), and the point question asks a real "why".
- **`12-broadcast/01-frames-on-the-wire`**. "Bytes, not messages" is exactly the right first idea, and "unfinished is
  not broken" names the key distinction. Needs the `loop { match stream.next() {...} }` shape shown on other data.
- **`12-broadcast/17-replay-check`** + **19 boss**: the step-function/golden-file design is the world's best "why"
  lesson (no sockets, no clock → identical every run), and it pays off in the boss.

Two structural patterns:

1. **Name-drop then move on.** World 11 lessons use bullets of the form "**`X`**: does Y" with no situation, no
   failing first attempt and no "why". CONTENT.md's "situation → it happens → the name" and "the compiler is a
   character" are absent: no quest in either world shows the compiler error you'd get by doing the obvious thing
   (e.g. 11/01 calling `square!(next())` with the naive expansion and watching the test count two calls; 11/02 without
   `$(,)?`; 12/14 running `cut_folder` on the runtime and watching the tick test stall).
2. **The answer, but not the shape.** World 12 explains the API on the critical line and then gives that exact line;
   what a beginner actually can't do is the surrounding control flow (loop + match + early return, a running min/max,
   two rows swapped each iteration). Hints repeat the lesson line, so they add nothing.

### Example rewrite: `12-broadcast/11-names-vs-files` (body cards)

> The ESL asset checker compares the names on the sheet with the photo files in the folder. Before a show, a file
> called `Mos.png` for the player Moss is the difference between a blank player card and a one-second rename.
>
> **Same name, two spellings.** `normalize_name` (already written) lowercases, drops accents and keeps letters and
> digits, so `Zoë`, `zoe.png` and `ZOE` all become `zoe`.
>
> **How far apart.** The **edit distance** (Levenshtein distance) is the fewest one-letter changes that turn one word
> into another: insert a letter, delete one, or swap one. `moss` → `mos` is 1 (delete an `s`); `moss` → `mass` is 1
> (swap `o` for `a`); `moss` → `fen` is 4.
>
> **Small answers build big ones.** Write `a` down the side and `b` across the top. Each cell holds the distance between
> the start of `a` and the start of `b` up to that cell. The first row is 0, 1, 2, 3...: turning nothing into `m`,
> `mo`, `mos` takes that many inserts. Every other cell comes from three neighbours you already know: the one to the
> left plus 1 (insert), the one above plus 1 (delete), or the one up-left plus 0 if the letters match, 1 if not (swap).
> Take the smallest. The bottom-right cell is the answer.
>
> **Only two rows.** A cell needs just the row above and the cell to its left, so you keep `previous` and build `row`,
> then `previous = row` for the next letter. Turning a `bool` into 0 or 1 is `usize::from(a != b)`.
>
> (Code block on *other data*: the first two rows for `ab` vs `b`, built by hand with `push`, not the solution line.)
>
> **Chars, not bytes.** Loop over `.chars()`, so `ë` counts as one letter, not two bytes.

### Example rewrite: `11-mastery/01-macro-rules-basics`, missing "why" card

> **Why not a function?** `fn square(x: i32) -> i32` works for `i32` only; you'd need a second one for `u64`, a third for
> `f32`. A macro never sees a type: it copies the code you wrote into its template before the compiler checks
> anything, so `square!(3)`, `square!(2.5)` and `square!(chunk.size())` all work. The price: if the template pastes
> `$x` twice, the code in `$x` runs twice.

## What a true non-programmer would need (input for a "general programming" world)

By world 11-12 these are assumed and never taught anywhere in the Rust track:

- **Compile time vs run time**: what a compiler does, what "the compiler generates code" means (macros, derives), what
  a build target/platform is (Windows exe vs browser wasm vs microcontroller).
- **Memory as a picture**: stack vs heap, what an "allocation" is and why it costs, why a growing list copies itself.
- **Counting cost**: "how many steps for 10 vs 10,000 items", linear vs constant lookup (scan a list vs a hash map),
  O(n) / O(n²) in plain words, and that measuring beats guessing.
- **Networking basics**: bytes, a stream vs a message (TCP vs UDP), ports, localhost, a socket, "the other side closed".
- **Data formats**: JSON objects and arrays, CSV rows and headers, text vs bytes (UTF-8, why `ë` is two bytes).
- **Waiting vs computing**: what a thread is, what "blocking" means, why a UI freezes, concurrency as a kitchen
  analogy.
- **State machines and flags**: remembering the last value, "fire once", time windows; how to reason about events
  arriving over time.
- **Libraries and dependencies**: what a crate/package is, versions (semver), reading API docs to find a method like
  `enumerate_pixels` yourself.
- **Testing ideas**: a test as a spec, deterministic tests (pass time in), golden files, "already green" tests that
  guard behaviour.
- **Algorithms as recipes**: min/max with a starting sentinel, running totals, "build the answer from smaller answers"
  (dynamic programming), with traced examples on paper before code.
- **Domain literacy**: each themed world needs a "what are we building" picture with the jargon glossed once.
