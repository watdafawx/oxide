# Curriculum audit: rust worlds 08-async, 09-systems, 10-apps

Scope: every quest.toml + lesson.md (plain) in the three worlds; games flavour skimmed for 08/01, 10/06 and all
flavour titles; starter vs solution diffed for 08/01, 08/07, 08/09, 09/03, 09/06, 09/09, 10/08, 10/09, plus TODO
grep on the bosses. Already known and not repeated in detail (see docs/PLAYTEST-2026-10-20b-rust-07-09.md,
docs/PLAYTEST-2026-10-20b-rust-10-11.md, docs/REVIEW-2026-10-19.md): API-call "used before taught" gaps (now
patched with "small tools" bullets), quiz answer-length bias (fixed), stacked hard-quest rhythm, first-build
times, duplicate `06-`/`07-` folder numbers, bosses with too few hints.

This audit is about something different: **do the lessons explain concepts and the *why* to someone who has never
programmed?** Short answer: no. These three worlds are written for a working developer who already knows what a
thread, a byte, hex, a pointer, HTTP, JSON and SQL are. The earlier playtests patched *API names* in, which made
the lessons longer bullet lists without adding the missing *ideas*.

## House-style compliance (applies to all three worlds)

`docs/CONTENT.md` asks for: unlabeled intro, 4-7 kicker cards ("**The word for it.** ..."), one code block,
situation -> it happens -> the name, each new word in bold with a plain gloss. `01-foundations` follows this (28/28
lessons use kickers, 0 use a "Why now:" label). Worlds 08/09/10: **34 of 34 lessons open with a `**Why now:**`
label, and 1 of 34 uses kickers.** They are bullet lists of facts with a code block, several with 2-3 code blocks and
a trailing "small tools" glossary — exactly the "lesson that turns into a glossary" the spec warns against.
`docs/tracks/rust-terms.md` has **no rows at all for worlds 02-11** (it jumps from 01-foundations to 12-broadcast),
so nobody can check "used before introduced" mechanically for these worlds.

## World 08-async (12 quests)

| Beginner clarity | Experienced-dev value | Coherence/sequencing | Task-lesson fit | Overall |
|---|---|---|---|---|
| 4 | 7 | 6 | 6 | **5.5** |

**Verdict.** For someone who already knows threads, this is a tight, accurate tokio tour: futures are lazy,
join vs spawn, bounded channels and the `drop(tx)` bug, the std-vs-tokio Mutex rule, select-based cancellation,
`.part` + rename. The downloader spine (games flavour) is real and the boss is a genuinely useful program. But
the world never answers the beginner's first question — *what is "waiting", and why can't I just use the threads
from world 07?* — and leans on unexplained words (runtime, poll, task vs thread, macro, `'static`, `Send`,
backpressure). The boss quietly introduces four major new tools (`Semaphore`, `JoinSet`, `res??`,
`Ok::<_, E>` turbofish), contradicting its own line "Everything you need was in this world".

**Worst quests**
- `08-async/01-first-async-fn` — the most important conceptual quest of the world is 3 bullets. "A future: a
  recipe for work" and "tokio is that runtime" are labels, not explanations. Never says what a *runtime* does,
  why Rust (unlike JS/Python) needs you to pick one, why `main` needs `#[tokio::main]` (what is an attribute that
  rewrites a function?), or why async exists at all when world 07 already had threads (answer: a thread per
  download costs ~MBs of stack and an OS switch; a task costs bytes). The exercise (`greet`, `add_async`) is a
  normal function with `async` in front, so the learner can finish without understanding anything new.
- `08-async/11-boss-mod-downloader` — `Semaphore`, `JoinSet`, `join_next`, `abort_all`, `acquire_owned`,
  `res??` (nested `Result<Result<T,E>,JoinError>`), `Ok::<String, Error>(..)` turbofish, match guards and
  `tokio::fs` are all first introduced in the boss's "New tools" block. The spine in docs/TRACKS.md literally
  says "concurrent downloads with a semaphore" — that deserved its own quest (09.5 "At most N at once").
- `08-async/07-shared-state` — states "std::sync::Mutex: its guard cannot be held across an .await" with no *why*
  (the guard isn't `Send`, so the future can't move threads, and a blocked OS lock stalls the whole worker). Also
  teaches three things at once (tokio Mutex, RwLock cache, `yield_now`) and the `bump` exercise's
  read-yield-write is a deliberately weird pattern that is explained only in parentheses.
- `08-async/04-futures-are-lazy` (read) — "a paused state machine" and "polls" are unexplained jargon; this is the
  ideal place for the plain-English mental model (a chef with one stove and many pots) and it isn't there.
- `08-async/10-http-client` — uses GET, status 404/500, "JSON", "any serde type", `serde_json::Value`, indexing
  JSON with `v["title"]` — none of HTTP, JSON or serde has been taught yet (serde is taught in **10-apps/03**,
  two worlds later). A non-programmer does not know what a URL path, a status code or JSON is.

**Best quests (models)**
- `08-async/05-mpsc-channels` — one idea, a concrete motivation ("3 / 10 mods done"), the classic bug named and
  then tested (`gather_ends_with_zero_workers`). Model for "have the learner meet the mistake".
- `08-async/09-cancellation` — clear "why" (dropping cancels futures but not spawned tasks), the loop-select shape
  shown, test that proves promptness. Good experienced-dev value.
- `08-async/02-join` — the sequential `greet_twice` vs concurrent `join!` contrast plus a timing objective is
  exactly the "see it happen, then name it" approach; just needs the prose to match.

## World 09-systems (10 quests)

| Beginner clarity | Experienced-dev value | Coherence/sequencing | Task-lesson fit | Overall |
|---|---|---|---|---|
| 3 | 8 | 5 | 7 | **5.5** |

**Verdict.** The bytes -> bits -> cursor -> VarInt -> TCP -> Server List Ping arc is excellent and the boss is the
best boss of the three worlds (real protocol, real bytes, real payoff: ping your own server). Experienced devs get
idiomatic Rust (`get(..4)?.try_into().ok()?`, `?` in struct literals, safe wrappers around `unsafe`). But the world
assumes the learner already reads hexadecimal and binary, knows what a byte and a memory address are, and knows
what C is — none of which the track ever teaches. Quests 04-06 (unsafe, raw pointers, FFI) are a detour the pinger
never uses; their "Why now" lines claim the pinger "talks to the OS and to C through unsafe" and its "byte buffers
cross into C as raw pointers", which is false and a beginner will notice the boss uses neither.

**Worst quests**
- `09-systems/01-bytes-and-endianness` — first line of code is `0x1234_5678`. Hex notation, what `0x` means, the
  `_` digit separator, why one hex digit = 4 bits so two digits = one byte, and what a "byte" is (8 bits, 0-255)
  are never explained anywhere in the track (`0x` first appears in 07-concurrency/07 and the 07 boss's hash
  constants, unexplained). Endianness is defined, but *why* two orders exist (CPU design history vs network
  standard) isn't. Also the quest needs `try_into` and `.ok()?` stacking, a third concept.
- `09-systems/02-bit-ops` — `0b1011_0000`, "bit", "mask", "flag" are used as if known. No picture of a byte as 8
  switches. `const` is used for the first time in the track here with no mention.
- `09-systems/05-raw-pointers` — never says what a pointer *is* (a number: the memory address where a value
  lives). "Null, dangling or unaligned" are listed without glosses. Since `&` references in world 02 were taught
  as "borrowing" with no address model, the learner has no foundation. The exercise (`increment`, `sum_raw`) is
  unconnected to the pinger.
- `09-systems/04-the-unsafe-contract` (read) — lists "five things" including `static mut`, `unsafe trait`, and
  `union`, none of which the track has taught (union never appears anywhere). Good content for an experienced
  dev, a wall of unknown nouns for a beginner.
- `09-systems/06-ffi` — "the C runtime", "NUL-terminated", `c_char`, `Cow` — assumes the learner knows C exists and
  how C strings work. TODOs contain the whole solution (`CString::new(s).ok()?; then unsafe { strlen(c.as_ptr()) }`),
  so the task is transcription.
- `09-systems/09-varints` — after the playtest fix the starter TODO is now the full algorithm line by line
  (`let mut v = value as u32; loop: byte = low 7 bits; v >>= 7; if v != 0 set the 0x80 bit; ...`). The learner
  no longer has to think; the most interesting puzzle of the world became typing.

**Best quests (models)**
- `09-systems/10-boss-minecraft-server-pinger` — real motivation, staged objectives, a byte-exact example
  (`10 00 ff 05 09 "localhost" 63 dd 01`), safety requirement ("never trust the length blindly") built into tests.
- `09-systems/03-binary-parsing` — the cursor pattern is the right abstraction, shown once, then reused; "only
  advance on success" is a real lesson in why.
- `09-systems/07-tcp-echo` — the line "TCP is a stream, not messages" is exactly the kind of *why* the rest of the
  world needs more of.

## World 10-apps (12 quests)

| Beginner clarity | Experienced-dev value | Coherence/sequencing | Task-lesson fit | Overall |
|---|---|---|---|---|
| 3 | 6 | 4 | 6 | **4.5** |

**Verdict.** A survey of five ecosystems (SQLite, serde, axum, egui, Tauri) in 12 quests, so each gets 1-3 quests
and none gets its foundations. SQL is used from quest 01 (`CREATE TABLE ... INTEGER PRIMARY KEY`, `ALTER TABLE`,
`CHECK`, `ORDER BY`, `WHERE`) and never taught; HTTP (methods, paths, status codes 200/201/204/400/404/405/500)
is never taught; what a webview, a frame, or "immediate mode" mean is compressed into one table. The project spine
is scattered: the plain flavour builds a mods table, then a *notes* table, then Oxide's *Profile*, a *hello/sum/bump*
API, a *notes* API, mod-card text, a *counter*, XP commands, and finally Oxide's home screen — the learner can't
say what they are building. Experienced devs get useful patterns (thin Tauri wrappers, headless egui tests,
user_version migrations, `.optional()` for 404) but the Tauri quest teaches almost no Tauri.

**Worst quests**
- `10-apps/01-rusqlite-basics` — first quest of the world, sold as "the whole API fits on one screen", but a
  beginner meets SQL, a database, tables, columns, rows, primary keys, placeholders, SQL injection ("**Never**
  format values into the SQL string" with no *why*), prepared statements, closures over rows and
  collect-into-Result at once. Needs a "what is a database / what is SQL" quest before it.
- `10-apps/04-choosing-a-ui-stack` (read) — compares egui to **GPUI**, which the world never uses, with
  `cx.notify()`, "views that return elements", "Zed, Hopper" (Hopper is an internal app name the learner can't
  know; also used in 10/10). Terms "immediate/retained mode", "webview", "frame" are defined in a table cell.
  Fine for an experienced dev choosing a stack; opaque for a beginner who has never seen a GUI from the inside.
- `10-apps/05-axum-hello` — "A `Router` is a tower `Service`. In tests ... call `app.oneshot(request)`": tower and
  Service are unexplained jargon; HTTP methods/status codes are used as if known. `&'static str` return type is
  never explained. The exercise is a one-liner.
- `10-apps/09-tauri-commands` — the learner writes `xp / 100 + 1`, a push into a Vec, and two one-line
  `state.lock().unwrap()` wrappers whose exact code is in the TODOs. Everything Tauri-specific (`generate_handler!`,
  `manage`, `mock_builder`, the JS `invoke` side) is given. The lesson never shows the JS side, so a beginner
  doesn't see *why* commands exist (the web page cannot touch files; Rust can).
- `10-apps/08-egui-viewmodel` — good idea (model vs view, headless test) but plain flavour is a generic counter,
  and every TODO is the exact solution line (`// TODO: self.count = self.count.saturating_sub(1)`).
  Never explains what "every frame" means (the screen is redrawn ~60 times a second; your function runs each time).
- `10-apps/11-boss-oxide-in-rust` — 90 min, 7 objectives, and the "small tools" block introduces ~12 new items
  (`clamp`, `as_ref`, `map_or`, `is_some_and`, let-else, the borrow-in-match workaround, `ProgressBar`, `Modal`,
  `key_pressed`...). The genuinely hard part (borrowing `self.home` in a `match` while calling `&mut self`
  methods) is a real Rust lesson that should be its own quest earlier.

**Best quests (models)**
- `10-apps/07-mod-card-text` — a deliberate quick win, pure functions that make the UI testable, "no new crate or
  concept" stated honestly. Good rhythm model.
- `10-apps/02-transactions-and-migrations` — strong *why* ("next month's version must open this month's file",
  "a failed upgrade leaves the file untouched"); real-world value for experienced devs.
- `10-apps/03-serde-models` — clear motivation (old save files must still load), each attribute tied to a test.
  Should move earlier (before 08/10).

Two structural patterns:

1. **"Why now" is about the project, not about the concept.** Every lesson's first line says *which feature* needs
   the idea; almost none says *why the idea works this way* (why async instead of threads, why tokio's Mutex is
   different, why endianness exists, why placeholders prevent injection, why a webview needs commands).
2. **TODO-as-solution.** To fix "used before taught", the previous pass put the exact code into `// TODO:` lines
   (08/09, 09/06, 09/09, 10/08, 10/09, 08/11, 09/10). That satisfies the blind test but removes the thinking: a
   beginner copies without understanding, and an experienced dev has nothing to solve. The spec wants TODOs in
   plain words and the exact call only in the *last hint*.

### Example rewrite: `08-async/01-first-async-fn` (plain lesson, house shape)

> A mod downloader spends almost all its time doing nothing: it asks a server for a file, then waits half a second
> for the answer. With 40 mods, waiting for each in turn takes 20 seconds. You want to wait for all 40 at the same
> time, and Rust's tool for that is `async`.
>
> **Why not threads?** World 07 ran work on threads, and 40 threads would work. But each thread is a full worker
> the operating system has to manage, with its own memory, and a launcher may wait on hundreds of things at once.
> Waiting doesn't need a worker; it needs a note that says "come back to this when the answer arrives".
>
> **The word for it.** That note is a **future**: a value that stands for "an answer that isn't here yet". Putting
> `async` in front of `fn` makes the function hand back a future instead of running straight away. Nothing has
> happened yet; you are holding a ticket.
>
> **Cashing the ticket.** Writing `.await` after the call means "pause here until the answer is ready, and let
> other work run meanwhile". `jar_name(21).await` gives you the `String`. You can only pause inside something that
> can be paused, so `.await` is allowed only inside another `async fn`.
>
> **Someone has to come back.** A future can't wake itself up. A **runtime** is the program that keeps the list of
> paused futures and resumes each one when its answer arrives. Rust doesn't ship one, so you pick a crate: **tokio**.
> The line `#[tokio::main]` above `main` is an **attribute**, an instruction to the compiler; this one wraps your
> `main` so tokio starts first and runs it. Tests get the same with `#[tokio::test]`.

### Example rewrite: one card for `09-systems/01-bytes-and-endianness`

> **Counting in sixteens.** A byte is 8 on/off switches, so it holds 0 to 255. Writing bytes in normal numbers is
> clumsy, so programmers use **hexadecimal**, counting in sixteens with the digits `0-9` then `a-f`. Every byte is
> exactly two hex digits: `0x00` is 0, `0xff` is 255, `0x12` is 18. The `0x` just says "hex follows", and `_` is a
> spacer Rust ignores, so `0x1234_5678` is four bytes: `12`, `34`, `56`, `78`.

## What a true non-programmer needs that is missing (input for a "general programming" world)

- **How a computer holds data**: bits, bytes, binary and hex; memory as numbered boxes; what an address is; stack
  vs heap in one picture. (Needed by 02 ownership, 06 Box, 09 entirely.)
- **What a program is while it runs**: process, thread, the OS scheduler, "blocking" vs "waiting". (07, 08.)
- **Files and paths**: what a directory is, relative vs absolute paths, where apps should store data. (04 boss,
  08 boss, 10/10.)
- **Networks in plain words**: IP address, port, `127.0.0.1`, client/server, TCP vs UDP, what a protocol is.
  (09/07-10, 08/10.)
- **The web**: HTTP request/response, methods, URL paths, status codes, headers; what a browser/webview does.
  (08/10, 10/05-09.)
- **Data formats**: text vs binary, UTF-8, JSON (objects/arrays/null), CSV; what "serialize" means. (03 boss,
  08/10, 10/03.)
- **Databases**: tables, rows, columns, keys, the five SQL statements, why transactions exist. (10/01-02, 10/07.)
- **How GUIs work**: the event loop, frames/redraw, widgets, why UI and logic are separated for testing. (10/04,
  10/08, 10/11.)
- **Tooling vocabulary**: compiler vs runtime, library vs binary, dependency/crate, debug vs release build,
  "first build compiles C code" (what C is, why a C compiler is needed). (04/09, 08/01, 10/01, 10/10.)
- **Reading code shapes**: what `!` (macro) and `#[...]` (attribute) mean in general, what `::` paths are,
  what a generic `<T>` is in one sentence.
