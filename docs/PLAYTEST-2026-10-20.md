# Blind playtest: Oxide's first hour (2026-10-20)

Question: can a beginner solve each quest from the lesson, the quest.toml labels and hints, the starter code and its tests, plus the earlier quests of the same track?

## Method and honesty notes

- Scope: Rust `00-tutorial`, `01-foundations`, `02-ownership`; Java `00-setup`, `01-basics`. 44 quests, 38 with code. The games flavour was used wherever it exists, the plain quest otherwise (the 6 read-quests have no flavour).
- Each quest was copied to `%TEMP%\oxide-playtest\<quest>`. I read only `lesson.md`, `quest.toml` (hints hidden), the starter and its tests, and never opened a `solution/` folder. Rust ran with `cargo test` (`CARGO_TARGET_DIR` set to a temp folder). Java ran with `gradlew.bat test` on JDK 21.
- **I am an LLM, not a beginner.** I know Rust and Java, so my first attempts passed far more often than a real beginner's would. "Minutes" below are estimates from concept count and from what the lesson did not teach. I did not time anyone. Where I say "a beginner would need hint N", that is a judgement from what the lesson covers. Where I actually got stuck, I say so.
- Process slips, recorded: on `rust/02-ownership/05-slices` and `java/01-basics/02-integer-division` I printed all three hints in one call instead of one at a time. Both ran after I had decided I was stuck. For the five boss quests I also read every hint after solving, to audit what they cover. Those reads are marked "audit".
- Gradle was already cached on this machine, so I could not check the "about 90 seconds first build" claim. Oxide sets `JAVA_HOME` per run (`docs/TRACKS.md`), so I did not log my own JAVA_HOME problem. It points at a JRE 17, and I overrode it by hand to use JDK 21.
- Nothing is solvable-in-principle broken. Every quest passed after the changes noted. The problems are teaching gaps and confusing signals.

## Ranked top 10 fixes (by impact on the first hour)

1. **Java `00-setup/08` boss uses things nothing taught.** The lesson says "reminders from this world: parseInt, split", but this world never taught them. Add a short snippet to `07-printing` or the boss lesson: `split`, `trim`, `Integer.parseInt`, and `new int[] {a, b}`. Fix the "tip calculator" id. It blocks a beginner in their first Java hour (+15 min over plan).
2. **Teach `new int[] {..}` before it is needed.** `00-setup/08` and `01-basics/02` both return `int[]`, but arrays come in `01-basics/10`. `return {a, b};` gives five unhelpful errors. Add the one line to those lessons, or move the array-return to the arrays quest.
3. **`%n` trap in `01-basics/09`.** `00-setup/07` teaches `%n`. `09` tests demand `\n`. On Windows `%n` is `\r\n`. The failure output looks identical because the `\r` is invisible, so the learner cannot see why it fails. Use `isEqualToNormalizingNewlines` in the test (as `07` does), and have the lesson say `\n`. Oxide should also render `\r` in expected/actual diffs.
4. **Rust `foundations/12` boss, collections gap.** Needs `Vec`, `for x in &vec`, `BTreeMap`, `.join`, `collect` and `&mut` recursion, with no earlier lesson. It is the quest straight after the first hour. Add a short `Vec` lesson (or quest) before `12`, add a hint for the `needs:` line, fix hint 4's `bad`, and rename the guessing-game id. About +20 min over plan.
5. **Rust `10-option` and `02/05-slices` use untaught std calls.** `match` on string literals (`"planks" => ...`) and `str::find` appear only in TODOs. Add each as one lesson line. `find` needed hint 1 in `05-slices`.
6. **Lifetime messaging contradicts the content.** `02/08` says the next quest writes a lifetime by hand. `09` gives the signature. `05-slices` shows `<'a>` four quests early. Either let `09` have the learner write `<'a>`, or reword both lessons. Explain `'_` once.
7. **Rust `foundations/04`: `mut` in a parameter.** `swings_to_break(mut block_hp: i32, ...)` is a new syntax. Add a lesson line, or take `block_hp` by value and `let mut` inside.
8. **Java `03-reading-red` and `04-compile-error` signals.** "in two quests" is wrong (the next quest). The `UnsupportedOperationException: TODO` claim does not match the `null`/`0` stubs. Gradle prints every compile error twice, and the lesson's sample line number is off by one.
9. **Objective labels that the tests do not check or do not mention.** Rust `01-variables` objective 2 ("shadows `name`") is untested. Java `05-switch-expressions` needs an `IllegalArgumentException` that no label or TODO states. Add the behaviour to the label, or drop the claim.
10. **TODO comments that hand over the answer.** Java `01-primitives` (`return playerCount + joining`), `01-basics/04`, `08` and many Rust TODOs state the exact expression. That lets a learner pass without reading the lesson. Prefer "what to do" over the code to type. Low urgency.

Minor, not ranked: Rust `06` quiz asks about different lines than the lesson prompt; Java `03` quiz answers are all the second choice; Rust `06`'s first quiz answer is the first choice.
