# Blind playtest: Rust worlds 03-06 (2026-10-20)

Question: can a learner who finished worlds 00-02 and the earlier quests of the same world solve each quest from the lesson, the `quest.toml` labels and hints, the starter code and its tests? Follow-up to `PLAYTEST-2026-10-20.md` (worlds 00-02 plus Java), same method and format.

## Method and honesty notes

- Scope: Rust `03-collections` (13 quests), `04-errors` (10), `05-traits` (12), `06-smart-pointers` (11). 46 quests, 41 with code, 5 quizzes. The games flavour was used everywhere (all four worlds have it for every quest).
- Each quest was copied to `%TEMP%\oxide-playtest2\<quest>`. I read only `lesson.md`, `quest.toml` (hints hidden), the starter and its tests. I never opened a `solution/` folder. `cargo test` ran with `CARGO_TARGET_DIR` set to a temp folder.
- **I am an LLM, not a beginner.** I know Rust, so nearly everything passed on the first compile. "Est" minutes are judgements from concept count and from what the lesson did not teach, not stopwatch times. "Hints used" counts only hints I revealed while stuck. I was stuck twice (`03/09`, `04/05`), and both times only the hint's key line mattered.
- Process slip, recorded: while grepping for `ptr_eq` after solving `06/11`, I printed the line of the boss hint that contains it (the `remove` hint). I read it after the quest passed, so it counts as an **audit read**, not a hint use. I did not audit the other boss hints.
- A real beginner will be slower wherever the starter compiles but the borrow checker complains. I could not reproduce that friction, so the boss estimates are the weakest numbers here.
- First builds of `04/06`, `04/07` and `04/11` download `thiserror` and `anyhow`. This machine had them cached. I could not check an offline first run.
- Nothing is broken. Every quest passed, and `04/05` and `04/09` needed a fix after the first attempt. The problems are hidden requirements, a TODO that does not compile, and a few concepts that appear only in TODOs.

## Ranked top 10 fixes (by impact)

1. **`04/05` box-dyn-error: hidden trim requirement.** The tests need `trim()`, and no label, lesson or TODO says so. The failure shows `ParseIntError { kind: InvalidDigit }` with no hint about spaces. Add "fields are trimmed" to the label or TODO (as `07-anyhow` does) and test the newline case in the lesson text.
2. **`03/09` and `03/12`: `char::to_uppercase()` returns an iterator.** `first.to_uppercase() + &rest` gives `E0369`. Add one lesson line: `c.to_uppercase()` is an iterator, so use `.collect::<String>()`, `.to_string()` or `.chain(rest)`. `12` asks for the same uppercase.
3. **`04/09` TODO does not compile.** `filter_map(parse_mod_line)` fails with `E0631` (`&&str` against `&str`). Change the TODO to `filter_map(|l| parse_mod_line(l))`, or give `parse_mod_line` the `&&str` signature.
4. **`06/11` boss needs untaught `Rc::ptr_eq` and `let ... else`.** Teach `Rc::ptr_eq` in `03-rc` or `06-rc-refcell-graph` (it is in a test already). Add a line to the lesson for "end the `borrow()` before you `borrow_mut()` the same cell": `let parent = tech.borrow().prerequisite.upgrade();` as a separate statement. This is the highest-risk quest in the four worlds, and the estimate (+10) is the least reliable.
5. **The TODO comments in worlds 03-05 are the solution.** Most TODOs spell out the exact expression (`stacks.iter().copied().find(|n| ...)`, `ok_or("missing comma")?`). The three bosses (`03/13`, `04/11`, `05/12`) are close to transcription. Then the `06/11` boss, which needs design, is a cliff. Move the code into the hints and keep the TODOs as "what to do". This continues finding #10 of the previous report.
6. **Id and crate names that no longer match the quest.** `04/11-boss-todo-cli` (crate `err_boss_todo`) is a mod list manager. The previous report listed `01/12-boss-guessing-game` too. Rename, or note it in the lesson.
7. **World 04 opens at `02` and its first quest is heavy.** There is no `01-...` directory. `02-custom-error-enum` needs `Display` with `write!`, `split_once`, and matching `Some("fabric")` literals in one go. Renumber the world, and add the literal-pattern line to `02`'s lesson (also open from the previous report).
8. **Titles and summaries that promise things not in the quest.** `03/08` says "fold" (taught in `11`), `06/02` says "drop" (taught in `10`), `05/01` says "Define the Entity trait" (already defined), `04/08` label 2 says "works". `06/08` uses Minecraft mod ids in a Factorio world.
9. **Quiz answers are guessable.** The correct choice is the longest option in `04/04` Q2, `05/05` Q1, `06/04` Q1 and Q2. Shorten it or lengthen the distractors.
10. **Std calls that appear only in TODOs.** `.zip` (`03/03`, taught in `07`), `.copied()` (`03/01`), `ok_or_else` (`04/06`), `(0..=100).contains` (`04/07`), `rem_euclid` (`05/09`), `*x.borrow_mut() += 1` (`06/05`), match guards and `.map(Command::Toggle)` (`04/11`). Each needs one lesson line, or a TODO that names the call. Low urgency, since the TODOs usually do name them.

Minor, not ranked: `05/08` `PartialOrd` against derived `PartialEq` can disagree (not mentioned). The first build of `04/06`, `04/07` and `04/11` needs the network. Only `03/09` and `04/05` needed any hint, so the hints in these worlds are well placed where I used them.
